# SmartMaid 下一阶段分工开发文档：战斗决策与移动安全

2026-11-27｜供负责人分派与评审｜状态：**提案，未执行**。A–D 为责任角色，不预设人数；一人可兼任多个角色，但生产修复须由另一人按原输入复核。

**阶段目标：**在 26.2 专用世界查清战斗决策的计时、动作切换与目标失效问题，并能证明女仆在受阻战斗中没有自行挖掘或搭路。本阶段交付可复现的逐项结论，不以“修完五个 bug”为目标：五项目前是静态发现，不是五个已复现的缺陷。

**选题依据：**[P3 实测 §3.10–4](../handoffs/2026-11-26-p3-jump-calibration-baseline.md) 已证明北/东三格沟固定跑道去返程通过，四格沟在起点侧安全停止。Combat3 的攻击任务和靶标掉血证明攻击发生，但不等于自主战斗 Goal 已进入；一处墙与库存数量不变也不能排除其他位置的短暂破坏或放置。[战斗待修清单 §6–7](../../../SmartMaid/DEVELOPMENT_COMBAT.md) 已给出 COMBAT-01～05 的现象、优先级和场景，适合作为下一阶段主线。相比之下，强行跨四格会改变现有能力边界，M6 桌宠与 P5 模型需要不同环境和负责人，均不作为本阶段依赖。

## 1. 开工边界

- 交接参考点为 `feature/jump-calibration` / `0c55f68`，不是对执行日 HEAD 的假设。A 先核对分支、工作树和差异，记录实际 SHA；不同则先说明差异。不得覆盖用户修改、改动用户的设计文档、触碰个人存档、自动推送或合并。
- 26.2 是玩法验收版本；26.3 仅构建和测试。沿用 [Loom 测试操作卡](../handoffs/2026-11-24-loom-test-runbook.md) 和专用测试世界。同一 `SmartMaid/run` 同时只允许运行一个游戏进程。禁止为赶进度共写配置、输入、日志或世界。
- 不调整移动速度或跳表，不重做已完成的 P4 发布工作，不引入新公开协议，不把主动攻击当作自主战斗。不把四格跨越、无上限持续跟随、鱼竿、模型或桌宠纳入验收。

## 2. 分工与交接

| 角色 | 独占写入面 | 可先做的工作 | 交付给谁 / 何时算完成 |
|---|---|---|---|
| A 集成负责人 | 新的阶段记录、测试世界与运行调度；不代改其他人的模块 | 锁定 SHA、测试顺序和需求歧义；收集证据 | 给 B/C/D 同一基线与夹具编号；最后按问题逐项出具结论，列明未验证项 |
| B 战斗逻辑 | `MaidCombatGoal` 及必要的战斗决策实现、其单元测试 | 对照清单梳理计时、使用物品、目标生命周期；列每项的可证伪预期 | 向 C 提供观测点，向 A 提交失败轨迹 → 最小修复 → 同输入复测。未复现不改生产代码 |
| C 可观测性与夹具 | `MaidAutoTest` 的测试侧操作、战斗夹具与解析测试；不改战斗规则 | 用已有事件搭建脚本，只对缺失信号加测试观测。若必须在 B 的文件埋点，由 B 代落或交接后单写 | 给 B/D 版本化输入、字段说明、一个正对照和一个负对照。缺字段必须报未验证，不能默认为零 |
| D 独立验收 | 独立断言、回放结果和证据清单；不改 B 的实现或放宽 C 的阈值 | 按下表预登记预期；复用 P3 固定跑道和历史输入；准备双版本检查 | 向 A 提交同一 SHA 的玩法记录、构建日志、分版本测试 XML 和 26.2 静态报告 |

**顺序：**A 冻结基线 → B 读逻辑、C 做夹具、D 写判据可并行 → C/D 先验证观测本身 → A 排队运行未修版 → B 逐项处理可复现问题 → D 运行同输入并做集成回归。B 独占共享战斗逻辑，先 01/02，再 03/04；05 待决策。多人不同时改同一战斗类；运行权、待执行输入和证据目录由 A 显式交接。

## 3. 工作包与验收口径

| 包 / 主责 | 复现与比较 | 验收或停止条件 |
|---|---|---|
| W1 计时（01，B+C） | 固定距离、装备、目标，记录游戏 tick、Goal 实际调用 tick、动作起止与冷却。分开近战、远程、退让、连续走位 | 用游戏 tick 差对照设计值，不把一次 Goal 调用当作一个游戏 tick。未指定的间隔先报实测，不自行修改手感 |
| W2 动作切换（02/03，B） | 半血、持弓且有食物；分别观察拉弓→进食、正常行动被盾抢占、威胁解除后恢复。另跑满血及无食物对照 | 记录使用的物品、动作终态、血量及库存；没有无限持弓、普通动作相互打断或盾解除后永久停滞。进食后额外等待若无明文约定，先列决策项 |
| W3 目标生命周期（04，B+D） | 使用可区分的目标 A/B；依次让 A 死亡、离开范围、清空，再引入符合既有优先级的 B | 以实体 ID 和动作接收者判定：不再攻击失效的 A，正确改用 B 或退出；不能只凭任务结束文本签收 |
| W4 持盾语义（05，A 主责） | 对比固定 0.5 秒与威胁持续策略，记录短威胁、持续威胁、威胁解除时的持盾与移动 | A 提交最低时长、刷新、走位、冷却恢复四项预期，待产品负责人选定后 B 才改。用实际格挡状态和结算后血量验收，不按原始来伤推断漏盾 |
| W5 战斗移动安全（C+D） | 新专用世界设受阻路线、可破坏方块、空的候选落块位及已知石料；分别运行主动 `attack` 和可证实进入自主战斗 Goal 的输入 | 两类分开报。每类均要有行为激活证据；战斗窗口内归属于女仆的导航挖掘/放置尝试分别为 0，场地方块和库存前后一致。另用合法非战斗动作验证两类观测都能捕获；无正对照或未进入指定状态记未验证 |

**最小证据格式（建议，不是现有接口）：**每条记录包含 `runId / gitSHA / 游戏版本 / 世界 / 输入SHA256 / 起止tick / maidId / targetId / 触发来源 / 预期 / 实际 / 结论 / 证据路径`。动作切换加物品与前后状态；导航副作用记录尝试、是否成功、坐标和归属。先排除夹具施工、玩家动作；战斗已经发生不能仅凭 `status.combat`，副作用为零不能仅凭末帧。保留原始记录，不只存汇总。
