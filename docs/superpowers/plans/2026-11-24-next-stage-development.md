实施步骤：

2. 盘点现有 AutoTest 是否能通过真实服务端命令分发器执行 /maidtasks 并读取状态；不能把只调用 MaidAIBridge 的结果算作聊天命令验证。优先复用现有执行/断言机制；如需扩展，仅增加最小测试操作，不造新启动器或修改生产协议。
3. 固定输入与断言，覆盖下表；每次操作前后记录实际状态，异步任务等待明确终态并设超时，不只检查返回“任务已下发”。
4. 单机集成服与专用服务端的权限选择不同。独立测试目录验证专用服务端默认权限：非授权来源拒绝、授权来源可调用；同时确认集成服默认行为保持原样。不得通过移除生产 requires 来通过测试，也不改用户原配置。游戏世界操作仍在玩家在线的单机客户端完成。
5. 失败留输入、日志、前后状态；修复后以相同场景复测，恢复测试前的配置，正常保存退出。

| 场景组 | 最低覆盖 | 可观察断言 |
| --- | --- | --- |
| 槽位与箱子 | transfer、chestopen、chestput、chesttake，默认和显式数量 | 源/目标实际数量、总量守恒、openedContainer 目标正确 |
| 原子动作 | look、break、place、use、equip、store | 朝向/方块/交互或装备变化符合定义；箱子与物品无异常丢失 |
| 可选任务参数 | attack target、mine range/count、farm range、craft/smelt count | 显式参数进入真实任务并影响结果；攻击仅对测试靶标 |
| 拒绝路径 | 越界参数、无女仆、非法槽位、无已打开箱子、无权限 | 命令/回执拒绝且不修改世界与库存 |

烧炼场景预先放入足够输入和燃料；合成/采矿明确数量单位，避免将配方产出批量与目标数量混淆。权限测试与世界执行测试分开留证，解析夹具里绕过根权限上下文不作为权限验证。

## 6. P3：跳跃实测标定

这是下一项功能开发，先建立测量再决定是否修改参数。参考 `MaidActionExecutor.kt`、`MaidMoveControl.kt`、`MaidJumpTable.kt`、`tools/maid_jump_sim.js`、`tools/gen_jump_table.js`。

1. 从通过 N1/N2 的代码新建独立任务分支，先记录表文件哈希、现有属性/速度/摩擦条件和模拟器输出；不直接修改已验收分支上的跳表。
2. 新建 26.2 专用平坦标定世界，在安全平台准备下表场景，记录方块坐标、起点、目标、朝向与助跑状态。每场景先测 5 次；额外区分静止起跳和有助跑的结果，不混算。
3. 记录实际起跳/落地位置、用时、跌落与卡住情况、采用的路径和降级原因；通过标准在该轮输入中预先写明，不以事后放宽误差使结果通过。
4. 仅在偏差能稳定复现并归因到执行器/表数据时修复。按需重新生成 Kotlin 跳表，逐项解释表差异并验证生成幂等；不重新引入生产 Java 文件。
5. 修复后重跑同一场景及受影响的跟随、任务移动和战斗移动；保留战斗期间不挖不搭、坐下不移动等既有安全行为。

| 场景 | 目的 | 判定依据 |
| --- | --- | --- |
| 平地移动至目标 | 基准速度/停止行为 | 到目标容差，能停止，无持续抖动 |
| 单格台阶/矮障碍 | 正常跨障 | 安全落地、继续前进、不重复无效起跳 |
| 可达短沟 | 起跳时机与落点 | 预先标记的安全落地区内，无跌落 |
| 边界/不可达沟宽 | 安全失败或替代路径 | 不无限重试、不盲目跳入危险区域 |
| 不同朝向 | 排除坐标方向偏差 | 同等几何条件结果一致 |
| 坐下/战斗约束 | 回归检查 | 坐下不移动；战斗不挖不搭 |

退出条件：每个声明支持的场景 5/5 满足预定行为；失败场景保留限制或修复，不以平均成功率覆盖。产出标定表、差异说明和复测证据；仅交模拟器结果不能签真实标定通过。
