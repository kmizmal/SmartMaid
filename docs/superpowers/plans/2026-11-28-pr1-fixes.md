# SmartMaid PR #1 修复实施计划

> **实施者：**使用 `superpowers:executing-plans` 逐项执行；仅在用户选择子代理方式时改用 `superpowers:subagent-driven-development`。复选框是待执行事项，不代表已经修复或验证。

**Goal：**修复 PR #1 的六项审查发现，保留已标定的跳跃能力、桥接鉴权和存档兼容，并交付双版本回归证据。

**Architecture：**导航保留安全 A* 路线，以有界的局部探测保护直线回退；跳跃验证之后才接管移动。桥接将在线名单与遥测状态分开，聊天只向刷新后仍已认证的连接入队。存档保留每实体 UUID 和单一选档指针，仅在提交新指针后清理过期版本。

**Tech Stack：**Kotlin、JUnit 5、JDK 25、Gradle Wrapper 9.9.1、Fabric/Loom、Minecraft 26.2 / 26.3、项目 AutoTest。

**Spec：**[PR #1](https://github.com/kmizmal/SmartMaid/pull/1) 审查结论与下列修复约定。审查 head `e8e7fda23935db209702096b5f54aae0eddf99f2`，base `c7094701bea239a2ea8eb9033ee2cec3f206b1a5`。本文件是提案，不含实现或新增实测。

## 全局约束与方案取舍

- 只处理六项：P1 同步扫描；P2 误拒路线、落点验证、首次名单、热重载误报；P3 快照累积。长期任务回队对象丢失、非 OP 多人验收阻塞、入站消息限额另列，不混入修复。
- **导航：**只限扫描距离会继续误拒绕路，直接删除又会撤掉四格沟保护。选择「A* 优先 + 有界局部探测」：四格深沟不能裸跳或跌入，有安全桥/绕路则可达；浅洼不算深沟，未知区块不算已确认深沟。不调速度、跳表、跳跃输入或已有验收阈值。
- **桥接：**不靠提前开启遥测填充名单，不弱化 ACK 或传输校验，不增协议字段，专用服仍不开桥接。配置变化后不自动重发聊天，避免送到不同端点。
- **存档：**不退回单 owner 文件。保留「当前选中 + 切换前有效的选中版本」，另外保护同 owner 尚可能写盘的活体或卸载过渡 UUID。旧版 owner 文件及其他 owner/世界不删；`.latest` 仍是一行 UUID，不引入自动回退。
- 不增运行时依赖；只在隔离目录跑游戏、使用测试凭据，不碰个人存档。默认串行：任务 0 → 1 → 2 → 3 → 4 → 5 → 6；任务 5 可独立验证。无需子代理。不自动提交、推送、合并或发布；若后续明确要求提交，按工作包分开并使用本机协作模型 trailer 规则。

## 重点验收

| 最容易漏掉的边界 | 预期 | 归属 |
|---|---|---|
| 距离很远、区块边界、世界最低高度 | 固定查询预算；未知列不读地形、不是空气 | 1 |
| 有安全绕路、浅洼、任务更换目标 | 不误停；旧停止原因不影响新目标 | 1 |
| 起跳定位期间落点变化 | 不强制起跳；三格空旷跑道仍通过 | 2 |
| 首次 ACK 前后、重连、切换世界、热重载 | 名单正确，遥测不提前，消息不串端点 | 3、4 |
| 换档失败与换档后清理失败 | 前者保旧档；后者保新档并仅告警 | 5 |
